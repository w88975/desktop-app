# 上游 v0.12.0 对齐记录

> 上游发布 2026-08-17 · 本次对齐 2026-08-18 · 上一次对齐 v0.11.4（起始快照）

## 一句话结论

v0.12.0 绝大部分是上游自己的品牌搬家（`agents.craft.do` → `thecraftagents.com`），对我们零价值；
**唯一有价值的实质变更是「删除内置文档源 `craft-agents-docs`」**，已一比一移植。
借这次翻代码，另外处理了三条指向上游服务器的出站，并把版本号与上游脱钩。

## 上游改了什么

`git diff --stat upstream-tags/v0.11.4 upstream-tags/v0.12.0` → **57 文件，+621 / -322**

| 类别 | 波及 | 处理 |
|---|---|---|
| A. 删除内置文档源 `craft-agents-docs` | 16 文件 | ✅ 移植（URL 换成我们的） |
| B. 品牌域名迁移 `thecraftagents.com` | 大部分文件 | ❌ 忽略 |
| C. `bun.lock` +539 行 | 1 文件 | ❌ 忽略 |
| D. 新文档站的构建脚本与 workspace 配置 | 根 `package.json` | ❌ 忽略 |

### A. 删除内置文档源 `craft-agents-docs` ✅

上游把内置的文档 MCP 源整个删掉了，改为让 agent 去公开文档站取。**净效果：每个 session 少一条常驻 MCP 出站连接。**

对我们的价值比对上游还大：这个源硬编码指向 `agents.craft.do/docs/mcp`，
我们的 agent 会去检索 **Craft Agents 的产品文档**，然后照着它回答 AIDP 用户的问题。
不是无用，是有害。

上游连整个 builtin source 抽象层一起删了（`isBuiltin` 字段、三个豁免集合、`BUILT_IN_MCP_SERVERS`）。
我们跟着一比一删 —— 留一个零实现的扩展点只是死代码，而且它现在的形状是按 Craft 文档源长的；
将来要做我们自己的内置源，按需求重新设计比复活这个壳更快。

涉及 `packages/shared/src/sources/`（`builtin-sources.ts` 整文件删除）、`agent/core/` 三个豁免集合、
`resources/resource-bundle.ts`、`utils/toolNames.ts`、`server-core` 的 `SessionManager`、
`session-mcp-server`，以及两个 isolated 测试用例。

**唯一偏离上游的地方**：上游把「搜 `craft-agents-docs`」的指引改成了指向 `thecraftagents.com/docs`。
照抄等于让我们的 agent 去读 Craft 的产品文档，比现状更糟。我们改成指向本项目文档站
`https://docs-aiadp.hxsyai.com/`。

### B. 品牌域名迁移 ❌

上游把 app、下载、自动更新、分享链接、文档全部搬到新域名。按文件数这是 v0.12.0 的主体，
但**我们两个域名都不用**，跟了反而要再改一遍。涉及 `README.md`、`.dockerignore`、
`Dockerfile.server`、`install-app.sh/ps1`、viewer 的 `Header.tsx` / `vite.config.ts`、
各 `package.json` 的 `homepage`、`EditPopover.tsx`、`oauth-callback.test.ts` 等。

⚠️ 例外：`EditPopover.tsx` 起初被归到这一类，实际上它含一处 `mcp__craft-agents-docs__SearchCraftAgents`
调用提示 —— 是 A 类的一部分（引导 agent 调用一个即将不存在的工具），已一并修正。
**下次分类时注意：只看 diff 的行数和文件名会漏掉这种混在域名替换里的功能性引用。**

### C. `bun.lock` +539 行 ❌

看起来像一次大规模依赖升级，实际全是上游新文档站的 Astro 工具链
（`astro`、`astro-expressive-code`、`boxen`……），而 `apps/docs-site` 本身根本没进 OSS 仓库。<!-- docs-links-ok 上游未开源的目录，此处正是在说明它不存在 -->

**应用运行时依赖零变化，一个包版本都没升。**

### D. 文档站构建脚本 ❌

根 `package.json` 的 `docs:dev/build/preview` 脚本、`workspaces` 去掉 `!apps/online-docs` 排除项。
对应的目录我们没有。

## diff 之外的发现

这一节是本次最有价值的部分 —— 上游 v0.12.0 完全没碰这些，但翻代码时撞见了。

### ⚠️ 会话分享正在把内容 POST 到 Craft 的服务器

`SessionManager` 有四处 `fetch(${VIEWER_URL}/s/api…)`。用户点「分享会话」，
完整会话记录就上传到 `agents.craft.do`。这不是品牌字符串问题，**是用户对话内容实际流向第三方**。
我们没有自己的 viewer 部署，已整体禁用（详见下面的提交 ④）。

### 「更新源」实际是两条独立出站

不是一条。`apps/electron/electron-builder.yml` 的 `publish.url` 生成包内 `app-update.yml`
（electron-updater 的 feed），`packages/shared/src/version/manifest.ts` 的 `VERSIONS_URL`
是另一条，用于拉子进程二进制清单。**只改其中一条等于白改。**

### 文档链接有 5 处完全绕开 `doc-links.ts`

`doc-links.ts` 管着 14 个功能深链，但 `TopBar.tsx`、`ChatPage.tsx`（两处）、
`menu-schema.ts`、`menu.ts` 里各有一处直接硬编码的 `agents.craft.do/docs`。
每次改域名都得重新全仓搜一遍。本次全部收口。

### release notes 同步只写不删

`initializeReleaseNotes()` 把包内的发布说明写进 `~/.craft-agent/release-notes/`，
但从不清理包内已移除的文件。装过旧版本的机器上，**只删仓库里的文件不会生效**。
已补上剪枝。

### `getReleaseNotesList()` 没过滤非版本文件

`next.md` 会进入版本列表，`compareSemver('next', …)` 全程返回 `NaN`，排序结果未定义。
文件多的时候碰巧不显形；发布说明被清到只剩两个文件后稳定复现 ——
`getLatestReleaseVersion()` 返回 `"next"`。已按 `X.Y.Z.md` 过滤。

## 落地提交

分支 `chore/upstream-v0.12.0-align`，从 `develop` 切出。

| 提交 | 内容 |
|---|---|
| ① `refactor(sources)` | 移植上游：删除内置文档源 `craft-agents-docs` 及整个 builtin source 抽象层 |
| ② `refactor(docs)` | 文档链接收口到 `doc-links.ts`，统一指向 `https://docs-aiadp.hxsyai.com/` |
| ③ `feat(update)` | 禁用自动更新，断开两条指向上游的更新源 |
| ④ `feat(share)` | 禁用会话分享，阻断会话内容上传 |
| ⑤ `chore(version)` | 版本号 `0.11.4` → `0.0.1`，重置发布说明 |

### 关于两个开关

③ 和 ④ 做成 `FEATURE_FLAGS` 开关而非删代码，因为两者都是「暂时没有替代服务」而不是「不要这个功能」。
后续接入时一处还原。

| 开关 | 默认 | 环境变量 | 还原前提 |
|---|---|---|---|
| `autoUpdate` | `false` | `CRAFT_FEATURE_AUTO_UPDATE` | 自有发布通道就绪，且已重新指向 `electron-builder.yml` 的 `publish.url` 与 `manifest.ts` 的 `VERSIONS_URL` |
| `sessionSharing` | `false` | `CRAFT_FEATURE_SESSION_SHARING` | 自有 viewer 部署就绪，且 `branding.ts` 的 `VIEWER_URL` 已替换 |

### 关于版本号

15 个 `package.json` 此前全部沿用上游的 `0.11.4`。一旦选择性移植 v0.12.0，
我们就变成「v0.11.4 加一部分 v0.12.0」—— 没有任何一个上游版本号能诚实描述它。
统一改为 `0.0.1`，走自己的版本线，上游对齐版本只记在本目录。

`doc-links.ts` 的深链保留了一个同类开关 `DOCS_DEEP_LINKS_ENABLED`（当前 `false`）：
文档站目前只有落地页，14 个 `path` 原样留在数据里，站点补齐路由后改这一个布尔量即可启用。

两点注意，下次同步会再遇到：

- **`bun run typecheck:all` 断在 `packages/pi-agent-server`**，是存量红（缺 `tsconfig.base.json`、
  `@types/cacheable-request` 类型错误等）。它是 `&&` 串联，断链会**跳过后面的 `apps/electron` 和
  `packages/ui`**，必须单独补跑。
- **`bun test` 有存量失败**，且 `headless server smoke test` 与 `oauth.e2e` 会随机飘（后者打真实外网）。
  判断标准是「与基线逐条比对」，不是「全绿」。
